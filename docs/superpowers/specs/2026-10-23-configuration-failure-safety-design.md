# 配置读取失败时保护原文件

用户已确认仅完成 FIX-CONFIG-01，不混入其他修复。本轮不修改 Python、公开版本、界面或配置格式。

## 根因与方案

`ConfigStore.Load()` 把已有文件的读取和 INI 解析异常转换为空文档；后续写入由此覆盖原文件。`LauncherSettingsService.LoadSettings()` 在默认配置路径会写更新源，因此仅启动加载也可能触发覆盖。

采用最小方案：删除底层读取的异常转空文档分支。文件不存在时仍正常创建文档；已有文件读取失败时让异常回到现有公共 API 边界。`GetText/GetJson` 等继续返回调用者指定的默认值，`SetText/SetSecretText/SetJson` 等继续返回 false，不执行保存。

不采用自动删除、重置或内容修复方案：它们会猜测用户数据，并扩展本轮范围。也不增加长期只读标志；用户自行修好文件或解除占用后，同一个实例即可恢复正常读写。

## 文件与验证

- 生产修改仅限 `csharp/ShaheLauncher.Core/Configuration/ConfigStore.cs`。
- 契约固定：启动加载保留损坏文件；普通值、密文及设置写入均拒绝覆盖；暂时不能读取且允许文件替换的占用场景仍保护原文件；文件修复后恢复保存。
- 使用现有 MSTest、Core 与 SettingsService，不新增依赖或回调抽象。
- 原有正常配置、新配置、加密和 JSON 往返由受影响回归覆盖。
- 每次结果立即记入 `PROJECT_STRUCTURE.md`，执行步骤只维护在当前唯一活动计划。

## 完成边界

修复只保证读取失败不破坏原文件。配置损坏后返回默认值的既有行为保留；明确错误提示及保存失败误报另属后续修复。还原安全、服务恢复、发布入口和整体 AUDIT 待办均不在本提交内。
