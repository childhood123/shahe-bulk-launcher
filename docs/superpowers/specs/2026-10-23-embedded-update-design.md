# 内置更新与可读更新内容

## 用户要求与旧版问题

用户要求更新器内置主程序，不再单独维护一个程序；检测更新先显示更新内容文本框，再提供立即更新、稍后更新、忽略此版本三个可聚焦按钮。用户补充“稍后”是在下次启动软件时更新。

用户指定的旧版目录日志已证明检测到新版本，只是原来的内联提示没有被察觉。没有改写该目录或公网清单。准确时间、源文件和证据以项目结构及 user46-diagnosis.json 为准。

## 实现

- 普通启动路径仍保留单实例保护；主 EXE 接收 --install-update 时提前进入已有 UpdateRunner 安装流程，跳过主 UI/单实例。临时副本携带同名 .config 与根 DLL，等待旧 PID 退出，下载、验大小/哈希、可选签名解密、备份替换并重启。
- 移除独立 ShaheLauncher.Updater 工程和发布复制逻辑。新包只要求主 EXE，不再要求 updater.exe。默认 dotnet publish 同时创建空 Configurations 目录。
- 原生 WinForms 更新窗口首焦点在只读多行“更新内容”，随后 Tab 为立即更新、稍后更新、忽略此版本。不设默认安装按钮，阅读/选择不启动更新；Esc 或关闭只关闭窗口。
- 立即更新使用主 EXE 临时副本执行。稍后与忽略以单一 update_preference JSON 原子保存在既有 Configurations 配置文件中，避免多个配置写入半成功。
- 稍后只安排已展示的目标版本，当前会话不安装，下次自动检查确认同一目标后进入更新；如果目标变化先显示新内容。忽略替换原安排，仅抑制该版本的自动提示，手动检查仍可查看并重新选择。保存失败使用本模块的局部警告，不依赖已取消的通用保存反馈修复，不误报忽略/安排成功。
- 保留清单 force_update 字段用于兼容解析，但用户指定的三个选择均有效，不再因选择稍后而退出软件。

## 旧版兼容

已发布旧安装器要求包中存在 updater.exe，因此新增明确的 IncludeLegacyUpdateCompatibility=true 发布选项。它把主 EXE 按字节复制为旧协议文件名；没有另一个更新器工程或实现。主 EXE 检测该文件名与旧请求参数后使用同一安装代码。

普通发布不含此副本；首次向旧版推送时使用兼容包。当前未调整公开版本/清单，也未覆盖用户旧版目录。
