# 路径记忆最大 999 条设计

## 目标

将 C# 版本的路径记忆数量范围从原来的 `0–20` 统一扩展为 `0–999`，确保设置为 `21` 至 `999` 后能够保存、重载并实际保留相应数量的路径记录。

## 已确认要求

- 用户明确要求：“能记忆到999条记录就行，之前是20”。
- 默认值继续为 `10`。
- `0` 继续表示不记录路径。
- 所有现有中文文案保持不变，只有范围提示中的“最大20”改为“最大999”。
- Python 源码保持原样；Python 的最大值 `20` 仅作为原行为参考，C# 的最大值 `999` 是用户明确指定的产品差异。

## 当前问题

`MainForm.LoadApplicationSettings()` 已按 `0–999` 加载配置，但状态提交、管理器保存、右键“调整记忆数”、`AppPathHistoryService.ApplyHistoryCount()` 和路径记忆管理器仍限制为 `20`。因此 `21–999` 可以在启动时读入，却会在后续操作中被静默压回 `20`。

## 设计

在 `AppPathHistoryService` 中定义唯一的公开常量 `MaximumHistoryItems = 999`。`MainForm`、`PathMemoryManagerDialog` 和服务层统一引用该常量，避免各入口再次出现不同上限。

范围行为固定为：

| 输入 | 结果 |
| --- | --- |
| 负数 | `0` |
| `0` | 关闭路径记忆 |
| `1–999` | 保留原值 |
| 大于 `999` | `999` |
| 启动配置无效 | 默认值 `10` |
| 保存回调无效 | 保持当前有效值 |

降低数量时继续从列表尾部删除超出的旧记录；提高数量时不生成记录。保存仍使用配置键 `max_history_items`，不改变配置格式。

## UI 与无障碍

- 路径记忆管理器和右键“调整记忆数”两个数字输入框都使用 `0–999`。
- 提示文案改为“`(0=不记录, 最大999)`”。
- 保留 `AccessibleName = "路径记忆数量"`、现有 `TabIndex`、按钮、菜单、快捷键和焦点行为。

## 验证

- 新增运行时契约测试覆盖 `-1`、`0`、`20`、`21`、`999`、`1000` 和无效配置。
- 验证启动加载、服务应用、状态提交、管理器保存、历史裁剪和 UI 上限使用同一边界。
- 运行受影响回归、C# 未过滤全量、Python 对照、Python 编译、Release x64 和差异检查。
- 使用隔离配置进行真实 EXE 验证，确认 `0`、`21`、`999` 保存后重启仍保持原值，不修改用户正式配置。

## 非目标

- 不修改 Python 源码。
- 不改变路径记录结构、排序、去重、备注、隐藏路径或剪贴板行为。
- 不重设计对话框。
