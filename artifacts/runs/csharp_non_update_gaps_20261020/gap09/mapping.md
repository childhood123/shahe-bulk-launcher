# GAP-09 路径记忆最大 999 条映射

## 用户确认目标

用户于 2026-10-21 明确要求：“反正能记忆到999条记录就行之前是20”。C# 目标范围因此确定为 `0–999`；Python 原版 `0–20` 只作为历史行为参考，不再作为本模块的目标上限。

| 设置保存/重置 | `features/settings.py:176,267-271` | 20 |
| 右键“调整记忆数” | `features/app_paths.py:464` | 20 |

| 路径管理器输入框/提示 | `ui/settings_dialogs.py:474-478` | 20 |

默认值为 `10`；`0` 表示不记录；降低数量时裁剪列表尾部；中文状态、菜单和确认文案保持不变。

## C# 目标行为

- `AppPathHistoryService.MaximumHistoryItems` 是唯一上限，值为 `999`。
- 启动加载、状态提交、路径管理器保存、其他软件设置保存、右键调整、服务裁剪和管理器输入框全部引用该上限。
- 负数归 `0`，`0–999` 保留，超过 `999` 归 `999`。
- 启动无效配置恢复默认 `10`；保存回调无效值保持当前有效值。
- 提示只把“`(0=不记录, 最大20)`”更新为“`(0=不记录, 最大999)`”；其他中文文案、配置键、快捷键、焦点顺序、`TabIndex` 和 `AccessibleName` 不变。

## RED 覆盖

1. 共享最大值存在且等于 `999`。
2. 服务对 `-1`、`0`、`20`、`21`、`999`、`1000` 的归一化结果分别为 `0`、`0`、`20`、`21`、`999`、`999`。
3. 路径管理器接受并保存 `999`，提示为“`(0=不记录, 最大999)`”。
4. `MainForm` 的加载、提交和管理器保存保持 `21`、`999`，无效启动配置恢复 `10`。
5. 降低数量仍从列表尾部裁剪，提高数量不制造记录。
6. 保存其他软件设置时，已有 `999` 不会被压回 `20`，持久化后仍为 `999`。

## 边界

- 不修改 Python 源码。
- 不改变路径记录 JSON/INI 结构、排序、去重、备注、隐藏路径或剪贴板行为。
- 真实验证只使用隔离配置和隔离 EXE，不覆盖用户正式配置。
